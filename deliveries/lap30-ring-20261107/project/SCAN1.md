# 新赛道扫描器整车工程

当前十字岛修正候选的固件遥测标识为 `C11LAP30SCAN2`。Keil 工程入口为 `demo/mdk/rt1064.uvprojx`。请保留仓库目录结构，工程从 `firmware/camera_car/demo/user` 引用共享扫描器。控制、舵机、编码器、摄像头和 SDK 位于本工程。

## 识别与寻路

- 前台每个新摄像帧复用 R17 的分带阈值做轻量扫描。出现候选或 R17 正在进行环岛引导时做完整多区间扫描。串口状态行 `SP_SCAN` 包含类型、置信度相关诊断和入环放行状态。
- 扫描器参与接近及正式入环的放行。完整扫描失败、区间溢出、相互冲突、十字岛证据或反侧环岛证据都会阻止入环。截边导致拓扑不足时，由 R17-2 当前帧的环岛边界、入口进度、路径及 12 像素岛边余量共同决定是否入环。正式切换后的同帧路径仍要复核。
- 环内和出环继续执行 R17-2 路径及原停车保护。
- 十字岛确认后，从当帧两侧通道中优先选离车辆中心较近的一侧，距离相同时优先选较宽的一侧。选定后锁边，沿与车前近场连通的当前道路像素生成转向目标，并沿用原低可信视觉限速。靠近出口时必须看见两侧汇入同一条前向通道，随后连续三帧确认普通道路恢复才退出十字岛。断路、冲突、多岔无法判定或超时交给原失线保护。
- 通过 `CROSS30 phase/side/clear` 查看十字岛状态。phase 1 为绕岛，2 为出口确认，3 为失去有效通道。当前候选以“前方唯一汇合出口”为路线条件，未覆盖需要转入侧面出口的布局。

## 复核

在仓库根目录执行 `python deliveries/lap30-ring-20261107/tools/run-host-checks.py --current`。将环境变量 `ZIG` 指向 Zig 编译器。共享扫描器另有 `firmware/camera_car/tests/run_tests.py`。

主机回归覆盖灰度分带、普通循迹、起步、环岛、条纹、停车、十字岛左右锁边、出口恢复和失线停车。历史手推回放 239 帧中有效 228 帧，和 R17-2 一致，两处正式入环仍在第 61、141 帧。该序列岛体常常截边，通用扫描器未单独确认环岛。Arm Compiler 6.21 命令行完成构建。板端时延及实车表现待验证。

本仓库已有的 R17 固件、日志和校验清单是历史发布记录。SCAN2 需从候选源码重新构建。
