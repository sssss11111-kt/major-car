## 当前控制链

LAP9及outputs补丁：MT9V03X采集188×120灰度 → 主循环复制完成帧 → 图像处理 → 有效性与误差 → 舵机比例控制；PIT每10ms采样两轮编码器，解析命令、执行保护、计算两轮速度输出。屏幕5Hz刷新，SNAP9在停车时发送同帧灰度和边界数组并附CRC。

关键配置来自上午分支 main.h/pid.c/isr.c：左PWM C6、DIR C11 HIGH；右PWM C8、DIR C9 LOW；编码器左负号、右正号；舵机C30/50Hz、命令范围85～100、中值92.5；速度目标30 counts/10ms，前馈1500，PWM上限3000/10000。counts/10ms不能解释为百分比或物理车速。早期 main 的左C7/双HIGH资料不能覆盖后期实测配置。

LAP10保留原检测器，增加 single_edge.c 状态判断：控制行90附近5行同侧连续、白色路径检查、直道宽度模型；单边阶段目标20 counts/10ms、最长0.5秒，连续3帧可靠双边恢复；起步仍要求双边与模型就绪。重新标定后第90行参考宽度142像素。

本地《本次检查与烧录.md》和 flash-recalibrated-result.json 记录 LAP10 新标定版本60864字节读回一致，SHA256为669e63c81f4fe62736eebcc05d5c919c132749b212f41d0315731812a6415864，最后状态为核心暂停、待冷启动。HANDOFF.md和candidate-status.json仍含较早“未烧录”说明。这里只确认历史文件相互关系，不能据此断言此刻车上实际版本或已通过冷启动。

## 优先问题与依据

1. **有效性与控制误差的数据范围不一致。** img_process.c第414行仅要求全图动态范围与30行可用；第416行在近端误差样本为空时默认画面中点。可复现为“看不见控制区域仍判有效且误差0”，不应直接作为可靠控制帧。
2. **跳变拒绝与历史回填形成无法重捕获的状态。** 第393行拒绝与历史相差超过22px的行；第468～477行把旧中线填回并写成新历史。稳定偏移40px也被持续拒绝，缺少历史老化和重新捕获路径。
3. **未把初始化接口接入真实main。** 静态s_last_center默认为0，第一个调用会把0当作有效历史；测试每次先reset掩盖该差异。本次证明影响首帧，未发现它必然导致永久不识别。
4. **统计、最终中线、控制误差不是同一次验收后的结果。** usable和误差在第400～427行计算；第433～450行又可能清除/移动中线，未重算有效行和误差。第457行以后插值/沿用历史也未单独标记，显示的连续线不能等同于本帧观测可靠。
5. **替换outputs会回到LAP9控制入口并绕开本地LAP10约束。** 它不是LAP10上的增量补丁：没有LAP10的启动模型匹配、单边时限和单边降速。是否更换应由明确的行为与回放证据决定，不能直接按说明覆盖。

## 说明文件中需纠正的推断

- 旧auxiliary_process会逐行更新mid_point，不是每一行固定从94出发；原函数也没有说明中声称的30+y补宽逻辑。
- fault4的判断是“图像年龄≥20tick **或** !good_frames”。一次处理结果无效就清零good_frames，随后10ms PIT可立刻停车，并不要求连续无效200ms。200ms对应的是没有新鲜帧的另一条条件。
- 132210为停车后的请求帧，不是故障触发瞬间。它能证明旧第90行右哨兵会拒绝该帧，不能独立证明此前所有停车由同一原因造成。
- 缺失边界没有真值，“该图真实误差就是0”没有独立标注支持；新算法输出0不能自行充当真值。
- 阈值下限只会把阈值往上推，不能证明避免高阈值；x86耗时也不能证明RT1064达到估计的0.5～1.5ms。
- 新函数实际只读输入，main新增line_image又复制22560字节；此项可后续优化，但应先解决行为问题再改性能。
