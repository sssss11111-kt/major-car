看了代码，这份例程用的是 **“逐行扫线找左右边界 → 取赛道中线 → 根据中线偏差控制舵机”** 的视觉循迹方法。

具体流程是：

1. **大津法（Otsu）二值化**  
   自动计算阈值，把摄像头灰度图转成黑白图，方便识别赛道。它属于图像预处理。

2. **从下往上逐行扫线，寻找左右边界**  
   核心在 [img_process.c 的 auxiliary_process()](C:/Users/Tong/Documents/ChatGPT/智能车/analysis/camera-example-20261021-111809/demo/user/src/img_process.c:92)。每行从当前中点分别向左、向右扫描，遇到**连续三个黑像素**，就记录为对应边界；随后计算：
   ```c
   中线 = (左边界 + 右边界) / 2;
   ```
   再用这一行的中线位置作为上一行的扫描起点，继续向上寻找。因此可以称为 **基于上一行中点引导的逐行扫线法**。

3. **选取一行中线，做比例转向控制**  
   在 [main.c](C:/Users/Tong/Documents/ChatGPT/智能车/analysis/camera-example-20261021-111809/demo/user/src/main.c:113)，取图像从顶部数约 **3/4 高度处**的中线：
   ```c
   mid_err = 图像宽度 / 2 - 该行中线位置;
   tmp_duty = 舵机中值 - mid_err * 0.5 * SERVO_DIR;
   ```
   也就是偏差越大，舵机转向量越大，属于 **单行前瞻的 P（比例）控制**。

所以，你问的“寻路算法”，在这里准确叫 **扫线取中线循迹**。代码没有实现八邻域爬线，也没有 A*、Dijkstra 这类地图路径搜索。另有 PID 用于左右电机的速度控制，与找赛道边界是两个环节。

## 6. 助手 · 2026-10-21T03:18:58.939Z

这个例程**没有单独的弯道识别和处理逻辑**，而是靠“中线跟着弯道移动，舵机根据偏差转向”来过弯。

具体分成两步：

**① 扫线时，让搜索起点跟着赛道弯。**

在 [auxiliary_process()](C:/Users/Tong/Documents/ChatGPT/智能车/analysis/camera-example-20261021-111809/demo/user/src/img_process.c:130) 里，从图像底部往上扫描，每一行找到左右边界后，计算中点，并把它作为下一行的搜索起点：

```c
_mid_line[i] = (_right_line[i] + _left_line[i]) >> 1;
mid_point = _mid_line[i];
```

所以赛道向左弯时，逐行得到的中线也会向左移动；向右弯则相反。

**② 用固定一行的中线偏差决定转向量。**

在 [main.c](C:/Users/Tong/Documents/ChatGPT/智能车/analysis/camera-example-20261021-111809/demo/user/src/main.c:113) 里：

```c
float mid_err = (MT9V03X_W/2)
              - mid_line[MT9V03X_H-MT9V03X_H/4];

float tmp_duty = servo_motor_duty_middle
               - mid_err * 0.5 * SERVO_DIR;
```

选取的那一行中线偏向哪边，就通过 `SERVO_DIR` 配置让舵机往对应方向修正；偏差越大，转向量越大，最后限制在舵机允许范围内。

**它对弯道的处理比较基础：**

- **缓弯**：只要边界能正常识别，就可以靠中线偏差跟随。
- **急弯或边界丢失**：没有专门的补线、弯道状态判断，容易出现中线偏差不准。
- **速度**：没有根据弯道程度自动减速，左右电机都跟踪固定的 `speed_target`。
- **转向**：只参考固定一行，没有多行加权或动态调整前瞻位置。

因此，它能完成基础的弯道循迹，但急弯表现会比较依赖车速、摄像头安装位置和转向系数。
