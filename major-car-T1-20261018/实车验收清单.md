# T1版实车验收清单

当前全部为待执行项。本轮没有操作硬件；日志中的PASS来自主机测试或构建。

## 1. 机械及版本

- [ ] 左转后回中、右转后回中各3次，位置可重复，摇臂/连杆/支架无松动。
- [ ] 接线保持昨晚已确认配置：左C6 PWM/C11 HIGH前进；右C8 PWM/C9 LOW前进；编码器符号左−1、右+1。
- [ ] 确认使用本次T1版真实摄像头候选；d同时返回历史DRIVE-CFG N和新增TRACK-CFG T1是正常的子系统标签。
- [ ] 上电待机、两轮不转；s/S能够停止输出；1500μs是否机械正中须现场确认。

## 2. 真实赛道与静态联动

- [ ] 固定相机，保存直道居中、左右偏移、普通左弯/右弯的原图与边线叠加。
- [ ] 各状态中找到真实边界；valid=1及quality=100均不等于边界一定正确。
- [ ] 赛道在画面右侧时误差为正，车头向右纠偏；左侧相反。
- [ ] w模式两轮始终零输出，舵机随图像正确转向，回到中央接近机械中位。
- [ ] 遮挡/丢线及图像超时后回中；记录零输出后的实际停止/保持情况。
- [ ] 检查真实细黑线和弯道没有被新增3像素、24像素几何阈值错误拒绝。

## 3. 受监护短时循迹

- [ ] 场地和车辆准备完毕后，先运行tracking_trial.py的默认预检。
- [ ] 明确执行--run后观察：200ms准备期无动力，之后两轮可靠起转，再进入PI调速。
- [ ] 居中直道、小幅左偏、小幅右偏能向中线收敛；每种条件重复至少3次。
- [ ] 分别验证普通左弯和右弯，再连接为连续路线。初期保持同一目标速度，不同时改多项参数。
- [ ] 独立验证3秒自动结束、s急停、通信断开、丢线/遮挡、图像超时；记录实际停车距离。
- [ ] 断链后不靠电脑发s作为唯一措施；车端应按最后接收的p时间超时，重新连上不能自动启动。

## 4. 记录与判断

每次保存固件SHA、参数、接线/相机姿态、电池状态、场地、视频与串口数据。重点对齐err10、target10、enc、pwm、us、phase、quality、cap_age、proc_ms和故障发生时刻。

phase：0准备、1起转、2双轮闭环、3非循迹模式。时间和处理耗时分辨率为10ms；proc_ms=0仅表示小于一个计时步长，不能当作没有处理开销。

故障归因应区分：识别边界错误、转向方向/范围、机械重复性、轮速起转/调速、图像过期、主循环超时和通信超时。不要用中位偏置掩盖松动或相机歪斜。

只有上述真实直道/普通左右弯及停止行为重复通过后，才把候选标为实车循迹版本。

## T1新增现场核对

- [ ] d显示TRACK-CFG v=20261018T1；新脚本拒绝旧T固件。
- [ ] seq持续增长，静态原图/边线稳定；记录真实DMA与处理时序，不能把主机缓冲测试当板上认证。
- [ ] ready=1对应连续3个有效已处理帧，accepted_age不超过150ms。
- [ ] 每次a只新增一个trial_id；正常到期后trial_done=1且trial_ms至少3200，随后p不能重新启动车辆。
- [ ] 主动提前s或故障后，工具结果为error，不能误记completed。
- [ ] completed只用于反馈与正常结束判定，轨迹及实际停车仍由视频/测距确认。
