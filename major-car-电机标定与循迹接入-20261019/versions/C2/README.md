# 左右轮分档标定候选 C2（0至70%）

用户将要求调整为0至70%分档测试。驱动板测得8.4V，C车模原配电机具体额定参数仍未确认；70%是本次试验指令上限，不是已确认的硬件额定能力。

基于T2的独立副本。CAR_CALIBRATION模式7，默认选定0%；P加5%、M减5%、D查询，L/R分别启动单轮2秒。仅待机可调档和启动；设置饱和在0至70%。p每150ms续租；500ms无续租、100ms前台超时、选侧反向小于-5或大于450计数/10ms、非选侧反馈绝对值大于10时停止，s在RX中断立即零输出。0%允许验证零输出，低档不转是有效观察，不伪称有电流或温度传感保护。

不为了达到70%取消450计数/10ms异常阈值；如果较低档已触发，则停止测试并记录实际到达的范围。该阈值不是厂商最高转速。手动观察异响、振动、温升等，异常时停止。尚未烧录，未运行新模式，尚无0至70%现场曲线。

原T2的1/2固定30%单轮命令、4/5/6速度闭环、循迹参数不变。CAL-CFG和CAL-START标识20261019C2。核心上限在car_core.h的CAR_CALIBRATION_MAX_DUTY单一维护，应用复用；主机工具严格核对cap7000和新标识，拒绝旧C1。

验证：calibration-70-red.log保留旧上限不能接受35%的失败证据；新增核心范围、隔离、到时停车、断联、前台、编码器、停止、回绕及应用调档/饱和/C2协议测试通过；MSVC完整回归通过，视觉48995项检查0失败。主机工具语法检查通过；完整主机串口会话和新固件现场行为待验证。ARM构建和固件SHA以VALIDATION.json及firmware/SHA256SUMS-C2.txt为准。

历史C1的0至30% HEX保留，当前候选使用firmware/20261019C2-calibration-0to70.hex。不要将C1与C2视为相同字节。

烧录前：电池关闭、DAP正确接入且核心板电源灯亮。先读取并校验本板当前4MiB完整备份，再写入C2并逐段回读；保持暂停，断开DAP，再电池冷启动。确认实际物理状态后才执行。局部pyOCD/IntelHex已安装，离线确认RT1064目标与官方Pack19算法。没有在准备环节访问下载器或Flash。

冷启动先查询，无Run不发L/R：
  & ./code/repair/test_calibration.ps1 -PortName COM9
单档执行（架空并观察后）：
  & ./code/repair/test_calibration.ps1 -PortName COM9 -Motor 1 -DutyPercent 5 -Run

现场顺序：0%、5%、10%……70%，每档左/右依次各单次2秒。每次核对自动输出归零，无异常后才进入下一档，异常不自动重试。取后半段采样均值和范围，保存CSV/原始字节并记录是否起转、异响和停止；比较同档左右反馈差。逐档从静止启动的结果只说明起转能力，不当作最低维持阈值。单位仍为编码器计数/10ms，真实RPM需编码器分辨率和传动比。
