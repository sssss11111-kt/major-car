## G1速度与保护

G1与L3独立低速模式共用`calibrated_wheel_step`：Kp1、Ki20/秒、10ms更新、积分±500，左前馈570+6.5×目标，右690+7×目标。30%起转最短200ms、最长300ms，连续3点反馈≥5确认；随后前馈至电机阶段1000ms，再初始化积分，使接入PI第一步输出连续，闭环最高15%，允许输出减为0，不设最低PWM硬限或自动再次起转。

循迹默认20计数/10ms，沿用图像误差减速至50%的规则；10～20动态目标未逐一做物理稳态标定。先200ms零电机转向准备，再最多3秒电机阶段，正常结束PWM0、回中。150ms图像时效、连续3帧无效、100ms前台、500ms通信租约、正向反馈450/反向−5、起转失败或持续500ms低反馈均可停车。`s/S`在RX中断立即清零、回中并清除积压命令，不是主动刹车；惯性停车距离需实测。无电流或温度测量保护。

H1历史左6%三次能维持，但L2对照时同一H1模式的左6%也停转；当时左7%、右8%可维持。不能把原维持档硬编码为永久下限或仅凭8.32V断言电压导致变化。

2. 车放在直道中央、正常落地高度、车头正对延伸方向，静态检查`valid=1、ready=1、good_frames≥3`及新鲜图像；同时看画面上的左右边界是否确为赛道。算法寻找白路面两侧黑边，不是单黑线跟踪。
3. 单独验证`w`静态视觉转向：两轮强制零，观察左右偏移的转向方向和回中。`w`可持续30秒，必要时提前s。**本步骤尚未执行。**
4. 静态方向通过后，再确认前方空间清空、车辆可自由运动且可随时切断电池；用当前`tracking_trial.py --run`只启动一次a，持续p续租，获取完整3秒或提前停止原因。不得直接沿用旧T2主机工具或手工发a后等待。
5. 要求观察车是否前进、是否左右偏、是否因丢线停车，记录起点/终点、可测的距离和偏移、用户实物观察。正常到时标志和两轮PI接管遥测是软件证据，不能代替实体观察。
6. 若发生故障、偏转或提前停止，保留原始串口与图像，先诊断，不自动重试、不延长时限或取消保护。第三目标通过后才讨论增加时长及更复杂赛道。

## 主机入口

在本归档根目录运行（命令本身不替代现场状态确认）：

```powershell
# 离线回归，不访问车辆
.\code\repair\run-tests.cmd
python .\code\repair\build_arm.py --mode camera

# 只查询；需要本机无线模块及已安装维护依赖
python .\code\repair\tracking_trial.py --port COM9

# 会真实发车！仅在上面的静态及地面准备全部满足后运行一次
python .\code\repair\tracking_trial.py --port COM9 --run
```
