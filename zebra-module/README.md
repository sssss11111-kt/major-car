# 斑马线发车与停车模块

给接手 AI：把 `zebra_run.c` 加进最新工程的编译目标，把 `zebra_run.h` 加进头文件路径。以最新工程的相机、循迹、PID、保护和电机接口接入。模块只返回识别结果和运行阶段。

## 视觉接入

- 每次处理一张新图，用最新工程的逐行阈值调用 `zebra_detect_bottom()`。传入灰度图尺寸、字节步长和可用行范围，排除车头遮挡。若最新视觉已有等价条纹检测，可直接输出当前帧通过多行确认的最下行。
- 检测器参数沿用 188×120 车载画面的像素尺度。每行至少 4 段黑带，连续至少 4 行且相邻中心差不超过 6 像素。返回 0 表示当前帧未确认。
- 把下边缘、帧序号和时间戳一并发布给控制循环。停车阈值用原始画面高度的 `3 * height / 4`，120 行时是第 90 行（从 0 编号）。条纹迟滞标志继续用于原循迹逻辑。

## 控制接入

1. 等待发车时保持零驱动。有效新图里同时有条纹和可信赛道才允许回中发车，沿用正式工程的发车延时，期间失去条件则重置延时。实际发车时调用一次 `zebra_run_start()`。
2. 仅在运行中按 **10 ms** 周期调用 `zebra_run_step()`。每轮传增量计数，前进阶段统一为前进正数，倒车阶段统一为倒车正数。使用正式工程标定的 `meters_per_count`（正数且单位为米/计数）。旧标定参考值为 0.00004620，60 cm 约为每轮平均累计 12,988 计数。
3. `LEAVE` 和 `LAP` 保持原循迹。累计 1 m 且条纹连续消失 5 帧才开放第二次识别。第二次连续 3 个新帧确认后清零里程并进入 `FORWARD`，回中舵机并低速直行。目标参数为 `ZEBRA_FORWARD_METERS = 0.60f`。
4. `SETTLE` 立即输出零驱动，两轮连续 10 个周期零计数后才允许换向。换向时重置速度 PID，`REVERSE` 回中低速倒车，参考目标是每轮每 10 ms 12 计数。倒车触发只使用换向后收到的新帧。
5. `DONE` 或 `ABORT` 当周期输出零驱动，锁定自动发车。倒车达到 80 cm 或超时也会结束。执行越线和倒车期间保留 STOP、摄像头帧超时、编码器异常和堵转保护。普通循迹丢线判据适用于循迹阶段，越线和倒车按自身距离、时间与相机新鲜度约束。
6. 让电机方向、PWM、舵机命令只由最终仲裁出口写入，防止视觉线程覆盖回中或停车命令。实际停车距离受滑行和打滑影响，需用正式车辆确认 60 cm 能让车尾过线以及倒车停位。

模块未接入最新算法，也未烧录实车。
