# 摄像头算法 V2：原因、参考与验收

基于 GitHub main `568eea999244b4d2e75547a309a803f5a5f5c5b5`，本地分支 `codex/vision-curve-rewrite`。软件验证日期：2026-10-21。没有烧录或实车通过结论。

## 原因判断

已确认旧代码把“路径有效”绑定到至少50%扫描行双边可见。合成左右弯中13行均有边缘支撑，但仅3行双边，旧算法判无效；控制连续3帧无效即停车。另有±24像素找白种子、全局单一阈值、未经有效性检查就学习宽度的问题。

“摄像头对比度不足”尚未被原图证实。当前接口只有188×120灰度，不能用HSV区分蓝色与白色；只能利用它们成像后的亮度差。局部亮度已经混同或过曝时，软件无法恢复不存在的信息。

## 实现

1. 自动模式逐行Otsu，固定阈值模式保留；逐行对比度小于16拒绝该行。
2. 白色连续段枚举、孤立1像素孔洞闭合、边缘两侧均值差至少10。极性支持原有黑路模式。
3. 从近处向远处关联，检查中心趋势、可见区间重叠和宽度，避免随意跳到另一白带。
4. 单边只能在另一边确实落在画外时推断。使用当前帧至少3个双边观测拟合宽度（跨度至少12行、残差不超过3像素、斜率有界），或最多8帧的真实宽度历史。推断结果不参与宽度学习。
5. 有效帧需至少2个近处双边锚点、至少2/3扫描行可信。全帧纯单边继续拒绝。无效帧立即废弃历史宽度，允许重新捕获。
6. `paired_rows`只统计真实双边，`inferred_rows`统计单边补中线。控制器、三帧丢线停车及舵机/电机参数未改。

串口新增 `rows`、`infer`、`contrast`、`auto`。`thr`及屏幕T在自动模式下仅为全局诊断阈值，二值图实际使用每行阈值；固定模式才是单一阈值。`contrast`同样是全局诊断值，不等于每行边缘可信度。

## 验证与回放

在 `firmware/camera_car` 目录运行：

```powershell
python tests/run_tests.py
python tests/test_replay.py
.\build.ps1 -Mode camera
.\build.ps1 -Mode mock
python tools/replay_vision.py captures --out tests/out/replay
```

`captures`需包含原始188×120、8位P5 PGM。目录按文件名排序；显式传多个文件时按给定顺序处理，历史跨帧保留。输出HTML、逐帧SVG叠加、原图、二值图、CSV和JSON。SVG区分实测中线与推断中线，不绘制不存在的边界。

新增测试旧算法：11场景5981项检查、127失败；新版最终：12场景6015项检查、0失败（含左右镜像、固定/透视宽度和30帧持续弯）。原场景套件144准确、6拒绝通过；另2个OBSERVE不计成功。核心、控制、应用、采图测试通过；回放工具4测试通过。Keil camera/mock均0错误0警告。构建日志在工程根目录，camera固件为 `demo/mdk/Objects/rt1064.hex`。

## 实车验收与限制

先停车采集直道、入弯、弯中、左右弯各段原始帧，固定曝光与安装姿态，回放查看边缘是否确在蓝白交界。曝光调节应以保留边缘灰度差为目标，不能只追求画面更亮。

上板测量处理最大耗时与有效帧间隔；50FPS目标意味着每帧周期约20ms，但主机测试不能证明板端实时性。核对当前车的接线、舵机方向/限位和已有标定参数后再低速试验；本工程来自GitHub基线，不包含工作区其他调试版本的电机标定。

仍有明确限制：冷启动反光连边可误判；内部2像素黑条可形成假边；1像素真边可能被闭孔抹除；120°镜头下线性行宽模型需要实拍校准。中心完全出画、全帧单边、环岛和十字不在此版本验收范围。不能据合成测试宣称实车弯道已解决。
