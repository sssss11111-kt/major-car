# RT1064 摄像头组 C 车模工程

2026-10-17 UART8修正版：专用UART8（MCU TX=D16、RX=D17）与UART1均支持命令和回传，115200/8N1。两路发送各自推进，不因另一UART等待而停止；UART8按厂家RTS（D26低有效）节流。启动时自动波特率握手，必须完整收到A5 FF FF才通过；`q`输出版本、收发/错误/丢行计数、握手结果及ASCII测试串。诊断B版已实测双向通信成功。详细构建与最终上车验证见仓库根目录 `repair/README.md`。本次修正不是前成员未上传源码的还原版本。

硬件：RT1064（带外置 SDRAM）、C 车模原配电机、DRV8701E 双路驱动、双编码器、BDS300 舵机、MT9V034 总钻风 120°普通摄像头、ST7735S 1.8 寸 128×160 屏幕。

默认使用真实摄像头，采集尺寸 188×120。提供完整 Keil 工程及库依赖；软件已编译和测试，实车方向、舵机限位、曝光和控制增益尚需校准。目标为直道和普通弯道低速循迹，不包含环岛、十字等特殊元素。

## 打开、编译和烧录

打开 `demo/mdk/rt1064.uvprojx`，目标 `nor_sdram_zf_dtcm`，编译器 ArmClang V6.21，器件包 NXP.MIMXRT1064_DFP.19.0.0。工程依赖本目录内的 libraries，不依赖 D 盘之外的旧工程。选择 CMSIS-DAP、SWD，在 Flash Download 中添加 `MIMXRT1064_QSPI_4KB_SEC` 算法，Flash 起始地址 0x70000000、大小 0x400000；选中 Reset and Run。Debug 初始化脚本使用 `demo/mdk/ini/evkmimxrt1064_flexspi_nor.ini`。烧录后断开调试会话并复位，验证冷启动。

PowerShell 命令行构建：

```powershell
.\build.ps1 -Mode camera
```

输出：`demo/mdk/Objects/rt1064.axf` 与 `rt1064.hex`。摄像头失败时，屏幕/串口报告故障，程序不会自动开车；检查连接后发送 `r` 重试。

模拟图像工程为 `demo/mdk/rt1064-mock.uvprojx`，构建命令 `./build.ps1 -Mode mock`。该模式不初始化摄像头并禁止电机输出，不能用它来确认真实摄像头或循迹效果。

## 程序结构

- `car_config.h`：引脚、编码器模式及符号、BDS300 脉宽、速度和转向初始参数。
- `car_servo.c/.h`：BDS300 上电中位初始化、PWM 换算、限幅和回中；详见 [舵机初始化说明](docs/servo-init.md)。
- `car_core.c/.h`：不依赖芯片的 Otsu/固定阈值、逐行边界、中线、PD 转向、双轮 PI、状态和停车判定。
- `car_app.c/.h`：CSI 图像快照、10 ms 控制定时器、串口命令、图像发送和 TFT180 显示。
- `isr.c`：保留逐飞摄像头中断链路；PIT 调用控制，UART1/UART8 接收命令及停车。
- `main.c`：时钟及调试串口初始化、应用初始化和主循环。

校赛原 `img_process.c`、`pid.c` 留作来源参考，不参与新工程构建。第三方逐飞/NXP 文件保留原版权与许可证；新增应用代码使用 GPL-3.0-or-later。

## 串口命令

UART1：115200、8N1、3.3 V TTL，TX=B12、RX=B13；专用无线UART8同为115200/8N1，MCU TX=D16、RX=D17，RTS=D26。启动时自动握手同步车端模块速率，`q`可查询ab结果。逐飞助手或串口工具都可以发送单个 ASCII 字符。不要发送带全角符号的命令。串口连接接线见 HARDWARE.md。

| 命令 | 功能 |
|---|---|
| `h` | 帮助 |
| `p` | 输出当前状态 |
| `q` | 输出UART8版本、收发/错误/丢行计数与波特率握手结果 |
| `a` | 启动循迹，要求待机且连续 3 帧有效真实图像 |
| `s` / `S` | 立即停车、故障确认；此命令在串口接收中断中执行 |
| `1` / `2` | 待机时单独测试左/右电机：5% 占空比、1 秒后停止 |
| `c` / `l` / `j` | 待机时舵机中位/小脉宽端/大脉宽端，保持 1 秒后回中；左右方向需实测 |
| `+` / `-` | 目标计数速度增减 5，上限 60；最初为 20 counts/10 ms |
| `o` / `t` | 切换 Otsu / 固定阈值 |
| `[` / `]` | 固定阈值减/加 5 |
| `e` / `E` | 待机时曝光加/减 64；范围 64～2048，初值 512 |
| `g` / `b` | 停车时发送一帧原始灰度/二值化图像 |
| `r` | 停车时重新初始化摄像头 |

默认每 500 ms 输出一行数据。`mode`：0 待机、1 循迹、2 电机测试、3 故障。`fault`：0 无故障、1 摄像头初始化、2 图像超时、3 连续丢线、4 主循环超时、5 编码器异常或无计数。

图像发送采用旧版逐飞灰度协议：`00 FF 01 01`，随后 188×120 字节。逐飞助手图像页面设置 188×120 灰度显示；兼容性仍需连接上位机验证。图像与文本不交叉发送，运行时拒绝新图传请求，避免低波特率的大帧占用调试通道。一次图传约需 2 秒，期间控制中断和停车命令仍有效。

## 第一次实车调试

1. 对照 HARDWARE.md 核对接线。先架起驱动轮，确认上电电机不转、舵机没有顶住机械结构。
2. 发送 `c`、`l`、`j` 检查 BDS300 中位和范围。默认仅使用 1350～1650 μs，是保守起点，不是实车测得限位。修改 `CAR_SERVO_CENTER_US/MIN_US/MAX_US` 后重新编译。
3. 发送 `1`、`2`，确认两轮都向前。分别调整电机方向电平；用 `p` 确认前进编码器计数为正，修改对应 `ENCODER_SIGN`。如果是带方向型而非正交型，将 `CAR_ENCODER_QUADRATURE` 设为 0。
4. 摄像头对准赛道，确认帧号增长、二值图中赛道内部为白、边界位置合理；改变照明并比较固定阈值与 Otsu。镜头安装高度、俯仰角和 120°畸变效果必须在真实图像中验证。
5. 将赛道向图像右边移动，检查中线误差为正。确认 `CAR_STEER_SIGN` 使车头转向赛道；方向反了先停车再改符号。程序只在循迹状态根据视觉控制舵机。
6. 在普通直道低速启动 `a`，用 `s` 停车。默认 PWM 上限 20%，目标速度是编码器计数单位，不能据此推断实际车速。先调比例，再小幅增加积分，最后调整转向 PD。

## 图像保存和测试

```powershell
python -m pip install pyserial
python tools/capture.py --port COM5 --count 10 --label normal
python tools/capture.py --port COM5 --count 10 --label bright
python tools/capture.py --port COM5 --count 10 --label dark
```

脚本先发送停车命令，再保存无损 PGM 原图；其他串口工具必须先关闭。COM5 仅为示例。

主机测试直接编译实际 C 核心与应用适配器：

```powershell
python -m pip install --target .tools ziglang==0.16.0
python tests/run_tests.py
```

测试覆盖中线偏差、光照、单边丢失、无赛道、启动条件、图像/主循环超时、停车、积分限幅、计时回绕、编码器无计数和图传完整性。适配器测试中的 MCU I/O 使用替身；它验证软件调用和状态，不代表真实外设已通过验收。构建和测试记录见 `docs/verification.md`。

新增合成图像测试覆盖 152 个场景（150 个识别/拒绝验证、2 个局限记录）及 17 帧移动/丢线/恢复序列。运行测试后打开 `tests/out/vision/report.html` 查看原图与识别叠加结果。反光连接边界和成簇黑噪声仍会造成中线偏差；这些场景记录为 OBSERVE，不计为准确识别通过。详细说明见 [图像场景测试](docs/vision-scenarios.md)。
